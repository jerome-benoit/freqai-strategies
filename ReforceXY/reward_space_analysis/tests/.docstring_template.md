# Test docstring template

Describe the behavior actually asserted by a test. Docstrings do not prove an
invariant, and an example copied into another test does not create ownership.
Use the [coverage mapping](README.md#coverage-mapping-invariant-ownership) to
resolve a complete registered ID and its owner.

## Standard format

Use these fields when they contribute information; omit irrelevant sections:

1. **Summary:** one sentence identifying the consumer-visible behavior.
2. **Invariant / invariant reference:** a complete registered ID. Declare
   ownership only at the mapped owner; identify non-owning checks explicitly.
3. **Context:** the condition and why it changes the expected behavior.
4. **Setup:** actual parameter values, regimes, seeds and boundary conditions.
5. **Assertions:** numerical expectations, transitions, bounds or errors checked
   by the implementation—not merely the presence of text or a section heading.
6. **Tolerance rationale:** the named tolerance and the residual/error being
   bounded. Do not invent accumulated floating-point error estimates.
7. **See also:** existing owners or documentation that resolves the contract.

Keep a simple test's docstring short. Use explicit setup/assertion sections for
multi-condition tests. For regressions, state the failing condition and expected
observable result; do not invent issue numbers or reserve an unregistered ID.

## Canonical exit example

This example documents the existing owner
[pbrs/test_pbrs.py](pbrs/test_pbrs.py)::`test_exit_step_shaping_matches_exit_step_rules`.
It is a docstring example, not a second implementation to add to the suite.

```python
"""Verify canonical exit releases the stored potential.

**Invariant:** pbrs-canonical-exit-semantic-106

The exit step uses the stored previous potential rather than recomputing it
from the exit's current PnL and duration.

**Setup:**
- Canonical mode, active hold potential, entry/exit additives disabled.
- gamma=0.94, stored prev_potential=0.42, current PnL=0.02.
- Current duration ratio=0.5; is_exit=True, is_entry=False.

**Assertions:**
- next_potential=0.
- reward_shaping=-0.42.
- pbrs_delta=-0.42.

**Tolerance rationale:**
- The owning test uses DECIMAL_PLACES_STRICT for zero next potential and
  IDENTITY_RELAXED for the shaping/delta comparisons to stored potential.
  These bound comparison residuals; they are not a policy-invariance proof.

**See also:**
- Coverage Mapping in tests/README.md.
"""
```

## PBRS mode and trajectory limits

Do not generalize the zero voluntary-exit rule to every exit mode. For a voluntary
exit with stored potential 2, gamma=0.95 and decay=0.5, the helper's next potentials
are:

| Mode                | Next potential                                         |
| ------------------- | ------------------------------------------------------ |
| canonical           | 0                                                      |
| non_canonical       | 0; additive terms can change canonical classification. |
| progressive_release | 1                                                      |
| spike_cancel        | 2 / 0.95                                               |
| retain_previous     | 2                                                      |

A voluntary exit is not automatically a terminal transition. Actual environment
termination clears next potential in every exit mode and sets shaping to
`-prev_potential`. Name the applicable transition/configuration and distinguish
additive reward from shaping.

For a complete ordered trajectory, verify the local identity
`F_t = gamma * next_potential_t - prev_potential_t`, adjacent potential
continuity, and the finite discounted boundary:

`sum(gamma**t * F_t) = -prev_potential_0 + gamma**T * next_potential_(T-1)`.

Canonical verification additionally requires the observed final next potential
to be zero and the applicable additive terms to be absent. Both zero-exit modes
are eligible under those conditions. For gamma below 1, the undiscounted sum of
shaping is not generally zero. Passing these checks supports only the trajectories
and assumptions exercised; it does not establish universal policy invariance.

[analyzer's PBRS configuration](../README.md#pbrs-configuration) for the current
contracts and diagnostic classification.
